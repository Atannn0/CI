# Building Multi-Agent Systems: Course Vault

Master's course in competitive intelligence. Created 2026-11-13. Language: English. Audience: students preparing a MAS or agent application project.

**Interpretation of the brief.** A study vault for students who must design, build, secure and deploy a multi-agent system or an agent app, and defend the design.

## Key takeaways
1. A MAS is justified by context limits, parallelism or specialisation, and it costs many more tokens than a single agent. Prove the need against a single-agent baseline. [[MAS purpose - when to use and when not]]
2. Most of the engineering is the harness: context, tools, verification, limits. [[What is a harness]]
3. Instructions guide; only code enforces. Security and deployment are part of the design, not an afterthought. [[Security checklist for student projects]]

## Learning objectives
After working through the vault you can:
1. **Explain** the difference between a workflow, an agent and a multi-agent system.
2. **Justify** the choice of a single agent or a MAS for a given intelligence question, using published evidence.
3. **Design** roles, relationships and delegation briefs for a MAS.
4. **Build** a working MAS with a minimal harness, with and without a framework.
5. **Evaluate** and **secure** the system with an eval set, a threat model and enforced limits.
6. **Deploy** it and report cost and reliability.
